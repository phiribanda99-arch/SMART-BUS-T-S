Smart Bus Transport System

Design Document

1. Introduction

This document presents the system design for the Smart Bus Transport System, a web-based application designed to manage bus routes, schedules, bookings, payments, and passenger travel records. The project supports multiple user roles including administrators, operators, and passengers.

The system is intended to provide a practical solution for intercity and regional bus operations. It enables staff to register buses and routes, assign schedules, and track seat bookings, while passengers can search trips and book journeys efficiently.

2. Objectives of the System

  • manage transport fleet information;
  • organize route records and schedule planning;
  • enable seat booking and payment capture;
  • issue tickets and maintain travel history;
  • provide role-based access to operational data.

3. Scope

  • user authentication and role-based access;
  • bus registration and status management;
  • route and district mapping;
  • trip schedule creation;
  • seat reservation and booking confirmation;
  • payment tracking and ticket issuance;
  • passenger travel history and records.

The system is focused on the business flow for a passenger transport company and is suitable for a small to medium transport operation.

4. Users and Roles

Administrator

The administrator manages the overall platform and controls the core system records. Responsibilities include registering and monitoring buses, creating routes, managing trip schedules, and reviewing bookings.

Operator

The operator supports the daily running of the system by handling schedule setup and fleet visibility. This role works closely with routes and availability.

Passenger

The passenger represents a customer who wants to search available routes, choose a trip by date and destination, book a seat, complete payment, and receive a ticket.

5. System Architecture

The application follows a simple three-tier structure:

  1. Presentation Layer: PHP pages and HTML forms
  2. Application Layer: PHP business logic and validation
  3. Data Layer: MySQL database with relational tables

This structure is suitable for a standard server-side PHP project without requiring a full framework.

6. Functional Design

Authentication Module

The system authenticates users through the users table. The login process validates the email and password, verifies account status, and loads the appropriate session value.

Bus Management Module

The bus module stores vehicle information such as registration number, make and model, year, bus type, seating capacity, and current status.

Route Management Module

A route is defined by route code, origin, destination, districts, distance, fare, and status.

Scheduling Module

The scheduling module links routes and buses to create a travel assignment. Each schedule contains route, bus, travel date, departure time, arrival time, fare, available seats, and status.

Booking and Payment Module

The booking module allows passengers to book seats for a schedule. Each booking includes a reference number, user, schedule, seat number, amount, and status.

Ticketing Module

When a booking is confirmed, a ticket is generated with a ticket number, booking reference, and QR code identifier.

7. Data Design

The database is organized around relational entities. The main tables are users, drivers, buses, routes, schedules, bookings, payments, tickets, and travel_history.

Core relationships:

  • one user can have many bookings;
  • one route can have many schedules;
  • one bus can be assigned to many schedules;
  • one schedule can have many bookings;
  • one booking can have one payment;
  • one booking can have one ticket;
  • one passenger can have many travel_history records.

8. Interface Design

Login and Registration Interface

The system provides a login form and a passenger registration form. It is designed to be simple and easy to use with clear validation feedback.

Admin Dashboard

The admin dashboard shows route count, bus count, driver count, booking count, and operational management forms.

Passenger Dashboard

The passenger dashboard allows users to search trips by origin, district, destination, and date; review schedules; choose a seat; confirm booking; and view travel history.

9. Security Design

The current system includes session management, hashed passwords, CSRF validation, and role-based access control.

Recommended production improvements: stronger input sanitization, encryption, activity logs, real payment gateways, and improved session security.

10. Non-Functional Requirements

  • reliability;
  • usability;
  • maintainability;
  • scalability;
  • performance.

11. Deployment Design

The system is designed for a standard web hosting environment with Apache or Nginx, PHP, and MySQL.

It is suitable for local deployment using XAMPP or a similar environment.

12. Risk and Limitation Analysis

  • no live external payment integration;
  • limited analytics and reporting;
  • basic UI styling;
  • minimal automation and testing;
  • no advanced monitoring or audit tools.

13. Conclusion

The Smart Bus Transport System is designed as a practical and functional web application for transport management and passenger booking. The architecture balances simplicity, maintainability, and operational usefulness.

The system successfully covers the main business workflow: users sign in, routes and buses are managed, trips are scheduled, passengers book seats, payments are recorded, and tickets are generated.
